# ch04 混合检索、重排与评估体系：开发记录

## 阶段 1：brainstorm 定稿（2026-10-07）

### 用户的关键原话

- "我要用 Superpowers 模式把客服系统的检索质量做上一个台阶:混合检索加重排,再配一套评估体系。"
- 功能需求 7 项（混合检索、重排、元数据过滤、Query 理解、生成质量控制、评估体系、前端配套）；验收 4 条；本章不做指代消解和多轮改写。
- 用户提供 `ch04.sql`（`low_confidence_questions`、`faith_cases` 两张表）。
- "方案A"（检索触发方式）。
- "方案A"（`faith_cases` 处置做台账页）。
- "方案A里面，输入dense的query能不能也标准化一下？"
- "rag_eval扩展到300题，其中D类拒答题60题。"
- 第 1、2、3、5 段设计："可以"。

### Claude 的关键产出

- spec：`docs/superpowers/specs/2026-10-07-ch04-hybrid-retrieval-rerank-design.md`。
- 分支：`ch04`。`ch04.sql` 逐字移到 `db/schema_ch04.sql`（shasum `f7b2575b…`）。
- 分类：架构级（Milvus 集合结构变化、`query_faq` 契约变化、新表、新评估体系）。
- 用户确认的决策：

  | 问题 | 决策 |
  |---|---|
  | 检索触发 | A：保持工具模式，自评在聊天服务中独立调用 LLM |
  | 台账处置 | A：`/admin/faith-cases` 页面 + 2 个接口 |
  | Query 理解 | A：检索管线内单独调用 LLM 改写并识别品类；dense 用改写后的问法，词表同义词只做替换；BM25 追加同义词 |
  | 评估集 | 300 题：A 70、B 60、C 60、D 60、E 50，每桶 3 个难度 |
  | 入池来源 | 证据为空也写 `self_check`（按 DDL 注释"本章只靠 useful 自评判入池"），用户未反对 |
  | 禁止承诺清单 | 5 条（到账日期、审核通过、赔偿、发货送达时间、保修外维修），用户确认 |

- 设计阶段的实测（一次性探测，不进仓库）：
  1. 本地 Milvus `run_analyzer(..., {"type": "chinese"})`：保留 `X3`、`Pro`、`S10` 等词项；区分大小写；`x3pro` 不拆分。据此加入查询侧的型号归一。
  2. pymilvus 3.0.2 的 `AsyncMilvusClient.hybrid_search(collection_name, reqs, ranker, limit, output_fields, ...)` 签名已核对。
  3. Context7 核对：BM25 Function、`SPARSE_INVERTED_INDEX`、`AnnSearchRequest`（`filter` 参数）、`RRFRanker(k=60)`、内置 `chinese` analyzer 等价于 `jieba` + `cnalphanumonly`。
  4. 执行器用 `tool.ainvoke(args)` 调用工具，拿不到 `content_and_artifact` 的 artifact。改为 `ToolOutcome` 增加 `data` 字段，由聊天服务渲染证据。

### 用户拒绝或纠偏的内容

- 评估集规模：Claude 提议约 110 题（D 桶 15 题），用户改为 300 题、D 桶 60 题。连带：知识文档扩容到 24 个型号，D 桶分 4 类，评估脚本加并发和子集参数。
- dense 查询：Claude 原方案的同义词只作用于 BM25。用户追问后，确定 dense 也做词表替换（不追加）。

### 翻车与返工

- 第 3 段原计划用 LangChain 工具的 `content_and_artifact` 传引用信息。写 spec 前读执行器代码，发现走不通，改为 `ToolOutcome.data`。

- 计划阶段的实测（临时集合 `ch04_spike_tmp`，用后删除）：6 字段集合 + BM25 Function 可建；`search(anns_field="sparse", data=[文本])` 只返回含查询词项的文档；`hybrid_search` + `RRFRanker(60)` + 两路同一 `filter` 正常；`describe_collection()["fields"]` 可用于识别旧结构。
- 计划阶段对 spec 的修订：
  1. 评估生成段必须先做真实的第 1 次调用，沿用模型给出的 tool_call id（DeepSeek 思考模式下自造 id 返回 400）。
  2. `Retrieval.ranked` 改为门槛前的排名，供评估计算 `hybrid_rerank` 的指标。
  3. 词表 `models` 改为"品类 → 型号"映射；问题中出现型号时，品类由型号决定，覆盖 LLM；改写失败时仍按型号定品类。
