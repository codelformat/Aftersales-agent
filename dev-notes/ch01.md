# ch01 纯对话：开发记录

## 阶段 1：brainstorm 定稿（2026-10-06）

### 用户的关键原话

- "我要用 Superpowers 模式做一个电商智能客服系统，第一步先跑通纯对话。"
- 功能需求："SSE 流式输出、逐 token 推送""用 PromptTemplate 模板化""用 with_structured_output 实现""历史消息裁剪加 token 预算控制"。
- 验收标准："curl 调对话接口能看到流式回复""第二轮能续上第一轮的上下文""能拿到结构化 JSON"。
- 对结构化提取方式："用A方式，你先测试一下可不可以"。
- 对 `.env`："你先不要管.env里除了我告知你的信息外的其他内容。token budget目前先设置为2000"。

### Claude 的关键产出

- spec：`docs/superpowers/specs/2026-10-06-ch01-pure-chat-design.md`。
- 分类：架构级（新项目的第一个子系统）。
- 用户确认的决策：

  | 问题 | 决策 |
  |---|---|
  | 历史存储 | A：服务端内存，按 `session_id` 存储 |
  | 结构化提取方式 | A：`function_calling`，提取模型关闭思考 |
  | token 预算 | 2000，代码常量，不读取 `.env` |
  | 实现方案 | 方案 1：LCEL 链，会话存储自己实现 |
  | 设计 4 节（架构、接口、数据流、测试） | 逐节确认，无修改 |

- 设计阶段做的实测（一次性探测脚本，放在 scratchpad，不进仓库）：
  1. DeepSeek 结构化输出：`json_schema` 不支持；强制 tool_choice 在思考模式下返回 400；思考关闭时 `function_calling` 正常；`json_object` 要求 prompt 含 "json"。
  2. LangChain 实测：`ChatOpenAI` 通过 `extra_body` 关闭思考后，`with_structured_output(method="function_calling")` 对 4 条样例全部解析成功。
  3. FastAPI 0.142.2：`ServerSentEvent(data=...)` 把中文转义为 `\uXXXX`，因此改用 `raw_data` + `json.dumps(ensure_ascii=False)`。
  4. FastAPI 0.142.2：yield 型 SSE 端点在函数体内抛出 `HTTPException` 时，客户端收到 200 和空流；在 `Depends` 中抛出时正常返回 422。因此预检放在依赖中。

### 用户拒绝或纠偏的内容

- Claude 曾计划读取 `.env` 中的 `TOKEN_BUDGET`，并提议调大预算。用户纠正：忽略 `.env` 中未告知的变量，预算固定为 2000。已同步修改 `CLAUDE.md`。

### 翻车与返工

- Context7 MCP 在会话启动后才添加，当前会话无法加载。用户重启会话后恢复。
- 实测结果与 mewhelp `.env` 注释矛盾：注释称"关掉思考，结构化输出会拿不到 tool_calls"，实测是强制 tool_choice 必须关闭思考。以实测为准。
- 4 条提取样例中有 2 条质量不合格："直接退钱，不想要了"被判为退款（可能应为退货）；投诉样例的期望方案复述了问题。已在 spec 中加入判定规则，并列入样例集。
