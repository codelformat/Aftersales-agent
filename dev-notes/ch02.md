### 用户的关键原话

- "我要用 Superpowers 模式给现有的客服系统装上查数据的能力，用 Function Calling 让模型自己决定调什么工具——工具链要长在客服聊天本身，用户在聊天页问一句就能触发。"

- "另外项目的重试机制都引入指数回退的时延方式"。

- 分支：本章在 `ch02` 分支开发（ch01 finish 时的流程改进）。

- 设计阶段的实测（一次性探测，不进仓库）：
  1. DeepSeek `adaptive` 和 `disabled` 两种思考模式下，都能对"订单 1001 的物流到哪了"选中 `query_logistics(order_id="1001")`。
  2. 回灌工具结果时不回传 `reasoning_content`，不报错。所以 `ChatOpenAI` 丢弃该字段没有影响。

  4. 第 2 次调用不带 `tools` 参数时，正常接受含 `tool_calls` 的历史并作答。
  5. 用最简 system prompt 时，模型在工具调用前输出了一句英文；换成 ch01 正式 Prompt 后，4 个问题都没有前置文字。
  6. 用 Context7 核对：SQLAlchemy 2.0 异步引擎与 asyncmy URL；LangChain `@tool`、`InjectedToolArg`、chunk 用 `+` 累积 tool_calls；OpenAI SDK 自带指数回退（初始 0.5 秒，上限 8 秒）。

## 阶段 10：Task 7.5 完成——真实上游冒烟（2026-10-06）

  - 连带影响："邮费"查不到在这次冒烟中不能证明任何东西，因为任何中文都查不到。
  - 修复（Codex 实现，Claude 验证）：新增 `db/mysql-client.cnf`（`[client] default-character-set=utf8mb4`），挂载到容器 `/etc/mysql/conf.d/`。DDL 不改。
  - `scripts/reset_db.sh` 新增中文校验。第一版用字符串比较，Claude 验证时发现它抓不到乱码：双重编码的数据经 latin1 客户端读出时会"反向还原"成正确中文。改为比较 `HEX(question)`。Claude 人为写入乱码后确认 HEX 校验失败，重建后校验通过；`messages.role` 的中文列注释也恢复正常。
- 修复后冒烟（uvicorn + DeepSeek + 重建后的 MySQL）：

  | 问题 | 工具 | 回答 |
  |---|---|---|
  | 退货政策是什么 | `query_faq(退货政策)` | 引用 7 天无理由、15 天质量问题，与 FAQ 一致 |
  | 邮费是多少 | `query_faq(邮费)`，结果为空 | "暂时没查到关于邮费的说明"，没有编造运费规则 |
  | 订单 1001 买的是什么？物流到哪了？ | `query_order` + `query_logistics` 并行 | 羊毛衫 ×2，918 元；顺丰，杭州转运中心，预计 10 月 7 日送达，与 mock 数据一致 |
