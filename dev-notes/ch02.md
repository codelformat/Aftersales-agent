# ch02 Function Calling 工具链：开发记录

## 阶段 1：brainstorm 定稿（2026-10-06）

### 用户的关键原话

- "我要用 Superpowers 模式给现有的客服系统装上查数据的能力，用 Function Calling 让模型自己决定调什么工具——工具链要长在客服聊天本身，用户在聊天页问一句就能触发。"
- 用户提供四张表的建表 DDL（conversations、messages、faq、tickets）。
- "MySQL起一个新的，按方案A走"。
- "用方案A，DDL 原样作为唯一来源"。
- "用方案A，连不上数据库就直接失败"。
- "用方案A，一轮里可以并行调多个工具"。
- "另外项目的重试机制都引入指数回退的时延方式"。

### Claude 的关键产出

- spec：`docs/superpowers/specs/2026-10-06-ch02-function-calling-design.md`。
- 分支：本章在 `ch02` 分支开发（ch01 finish 时的流程改进）。
- 分类：架构级（数据库骨架、工具基础设施、聊天链路改造）。
- 用户确认的决策：

  | 问题 | 决策 |
  |---|---|
  | MySQL | 本项目自己的 `docker-compose.yml`，宿主端口 3307；`.env` 新增 `DATABASE_URL` |
  | 建表 | 用户 DDL 原样保存为 `db/schema.sql`，作为唯一来源；ORM 只映射，不 `create_all` |
  | 数据库单测 | 用同容器的 `aftersales_test` 库；连不上直接失败，不跳过 |
  | 编排 | 第 1 次调用绑定工具并流式输出；有工具时执行后做第 2 次调用（不绑定工具）流式输出 |
  | 单轮范围 | 一轮内可以并行执行多个工具 |
  | 重试 | 全项目一律指数回退加抖动，统一用 `app/retry.py`；已写入 `CLAUDE.md` |
  | 设计 4 节 | 逐节确认，无修改 |

- 用户未纠正、按已接受处理的假设：会话历史改存数据库（`session_id` = `conversations.id`）；匿名 `user_id` 由页面生成；mock 数据按 ID 固定种子；`/extract` 不变；用 `ch02` 分支。
- 设计阶段的实测（一次性探测，不进仓库）：
  1. DeepSeek `adaptive` 和 `disabled` 两种思考模式下，都能对"订单 1001 的物流到哪了"选中 `query_logistics(order_id="1001")`。
  2. 回灌工具结果时不回传 `reasoning_content`，不报错。所以 `ChatOpenAI` 丢弃该字段没有影响。
  3. "订单 1001 买的是什么？物流到哪了？"一轮返回 2 个 tool_calls（`query_order`、`query_logistics`）。
  4. 第 2 次调用不带 `tools` 参数时，正常接受含 `tool_calls` 的历史并作答。
  5. 用最简 system prompt 时，模型在工具调用前输出了一句英文；换成 ch01 正式 Prompt 后，4 个问题都没有前置文字。
  6. 用 Context7 核对：SQLAlchemy 2.0 异步引擎与 asyncmy URL；LangChain `@tool`、`InjectedToolArg`、chunk 用 `+` 累积 tool_calls；OpenAI SDK 自带指数回退（初始 0.5 秒，上限 8 秒）。

### 用户拒绝或纠偏的内容

- 用户追加要求：项目中所有重试都用指数回退。Claude 原设计的工具重试间隔是固定的 0.2 秒、0.4 秒，改为公共函数 `retry_async`，按 `min(base × 2^(n−1), max) × 抖动` 计算。

### 翻车与返工

- 本机 3306 已被 mewhelp-mysql 占用，改用 3307。
- 用户回复"继续展示第 3 节"时，第 3 节已展示完；Claude 按"下一节"理解，展示了第 4 节，并在回复中说明。
