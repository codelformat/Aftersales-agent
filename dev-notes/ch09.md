## 任务 1：部署 Langfuse v4 并做 spike（2026-10-09）

### 用户的关键原话

- "Entrust as much work as possible to codex"（执行中途）。

### Claude 的关键产出

- Codex：`docker-compose.langfuse.yml`（按计划原样）；`uv add "langfuse>=4.17,<5"`（4.17.0）。
- Claude：`.env` 追加 3 个 `LANGFUSE_*`（随机生成密钥）；`docker compose -f docker-compose.langfuse.yml up -d --wait`，6 个容器健康，`/api/public/health` 返回 `4.56.0`。
- spike 结论（scratchpad 一次性探针，3 节点图 + 真实 DeepSeek 调用 1 次）：

  | 检查项 | 结论 |
  |---|---|
  | a. 代理 | 设不设 `NO_PROXY`，trace 都能到达（本机 Clash 转发回环地址）。保留 `_bypass_proxy` 作防护 |
  | b. 根 observation 带意图 | 通过：`IntentCallbackHandler` 写入后，根 observation 的 metadata 有 `intent=物流`；SDK 私有属性 `_run_states`、`_runs`、`root_run_id`、`_otel_span` 均可用 |
  | c. trace 级元数据 | v4 events_only 模式下 v1 `GET /api/public/traces/{id}` 返回 404；v4 的 trace 视图展示根 observation，意图在根 observation 的 metadata 中 |
  | d. token 字段 | `usageDetails.input/output/total`（另有 `inputUsage/outputUsage/totalUsage`） |
  | e. 过滤 | `traceName`、`sessionId`、`userId` 只在根 observation 上，子 observation 没有；`type=GENERATION` 过滤可用 |

- 判定：b 通过，继续执行。任务 4 改为两次查询（根 observation 取意图，GENERATION 取 token，按 traceId 关联，只统计 chat_turn 的 trace）。
