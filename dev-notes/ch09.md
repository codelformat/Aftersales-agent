- 用户确认的决策：

  | 问题 | 决策 |
  |---|---|
  | Langfuse 部署 | `docker-compose.langfuse.yml` 单独启停；未配置时不挂回调 |
  | 意图元数据 | 计划第 1 个任务做 spike，实测 SDK v4 在意图确定后写 trace 级元数据的写法；走不通时停下来问用户 |
  | 成本统计 | `scripts/intent_cost.py` 按意图汇总 token，不统计金额 |
  | `evidence_confidence` | `w1·top1 + w2·effective + w3·margin`，单门槛；评估集网格搜索 + 5 折交叉验证；规则沿用 ch04（可答保留率 ≥ 95%，D 拒答率最高） |
  | 闸 | 位置不变；knowledge 出口 conf + 自评；aftersales 出口只看 conf |
  | 👎 快照 | State 新字段 `retrieval`（Top-5 带分数），从 `aget_state_history` 回捞；SSE `done` 带 `message_id` |
  | 飞轮 | 进程内单 worker 队列串行；标准化 → 嵌入召回待审候选 → LLM 判定 → 累加或新建；失败行由 `run_flywheel.py` 补跑 |
  | 入库 | 通过时写 `flywheel` 块（`飞轮补充/<品类>`），同步 `vectorize_pending()`；`--rebuild` 保留 |
  | 评估流水线 | 只跑 `hybrid_rerank` 全量 300 题，写 `eval_runs`；`--trend` 标下滑；后台趋势页 |

- 读代码时发现的事实：现有闸只看 Top-1 ≥ 0.20，ch04 门槛扫描中 D 桶拒答率只有 50%；👎 只写 localStorage，`done` 事件没有消息 id；State 的 `evidence` 不带分数且每轮被覆盖。
- Context7 查询结论：Langfuse SDK v4 用 `propagate_attributes`（只作用于作用域内新建的 observation），`update_current_trace` 已移除；LangGraph 用 `compile().with_config({"callbacks": [handler]})` 挂回调。
