# ch03 知识库与向量检索：开发记录

## 阶段 1：brainstorm 定稿（2026-10-06）

### 用户的关键原话

- "我要用 Superpowers 模式给客服系统建知识库,把 query_faq 的内部实现从关键词查表升级成向量语义检索,工具的入参出参契约保持不变。"
- 用户提供 `ch03.sql`（`knowledge_chunks`、`qa_extraction_staging` 两张表）。
- 验收："「邮费是多少」这类换说法的问题,现在能召回运费说明并答对"；"故意中断建库任务再重跑,漏向量化的块能被捡起补齐"。
- "用方案A"。
- "设计可以。同意新增"（`.env` 新增 `MILVUS_URI`）。
- 第 2 到 5 节设计："可以"。

### Claude 的关键产出

- spec：`docs/superpowers/specs/2026-10-06-ch03-knowledge-base-design.md`。
- 分支：`ch03`。`ch03.sql` 逐字移到 `db/schema_ch03.sql`。
- 分类：架构级（新增知识库子系统、Milvus、嵌入接口）。
- 用户确认的决策：

  | 问题 | 决策 |
  |---|---|
  | Milvus 部署 | 本项目 compose 加 Milvus Standalone v2.6.22 + etcd + minio；宿主只暴露 19530、9091 |
  | 知识文档 | Claude 编写 3 份 Markdown，用户审核 |
  | 挖掘来源 | MySQL `conversations`/`messages`；演示用约 30 通样例历史对话 |
  | 定时任务 | 一次性 CLI + 系统 crontab |
  | 去重 | 向量召回候选 + LLM 裁定 |
  | 重复项 | 直接丢弃，知识库不变 |
  | 方案 | A：pymilvus 直连，集合只存 id + 向量；MySQL 状态驱动的两段式流水线（入库段写 `pending`，`vectorize_pending()` 统一向量化） |
  | 设计 5 节 | 逐节确认，无修改 |

- 用户未纠正、按已接受处理的假设：`faq` 表 12 条导入知识库；Milvus 主键 = MySQL 主键；检索时正文从 MySQL 读。
- 设计阶段的实测（一次性探测，不进仓库）：
  1. 硅基流动 BGE-M3 返回 1024 维、模长 1.0 的向量。
  2. 「邮费」「邮费是多少」「快递费」的第 1 名都是运费条目（0.649、0.686、0.682）；无关问题最高 0.425。据此定 `FAQ_MIN_SCORE` 初值 0.50，待评估集校准。
  3. 用 Context7 核对：pymilvus `AsyncMilvusClient` 的建集合、`upsert`、`search`；`OpenAIEmbeddings` 对非 OpenAI 服务必须设 `check_embedding_ctx_length=False`；`MarkdownHeaderTextSplitter`、`RecursiveCharacterTextSplitter` 的参数。

### 用户拒绝或纠偏的内容

- 去重方式：Claude 推荐"归一化精确匹配 + 向量相似度阈值"，用户选择"向量召回候选 + LLM 裁定"。
