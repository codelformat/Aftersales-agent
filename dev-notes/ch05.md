### Claude 的关键产出

- spec：`docs/superpowers/specs/2026-10-07-ch05-workflow-agent-design.md`。
- 分支：`ch05`。
- 分类：架构级（`/chat/stream` 主链路由 `services/chat.py` 换成 LangGraph 图，新增 checkpointer、新接口和前端按钮）。
- 用户确认的决策：

  | 问题 | 决策 |
  |---|---|
  | Checkpointer | `AsyncSqliteSaver`，文件 `data/checkpoints.sqlite`。LangGraph 官方没有 MySQL checkpointer（Context7 核对：InMemory、SQLite、Postgres、MongoDB 等） |
  | 置信度闸 | Top-1 重排分 < `GATE_MIN_SCORE` 或证据为空 → 兜底；否则调用 ch04 `self_check`，不够也兜底 |
  | ReAct 实现 | 方案 A：手写节点和回边，复用 ch02 执行器。不用 `create_agent` 预制件 |
  | Agent 工具 | `query_order`、`query_logistics`、`query_product` + 控制工具 `offer_human_options`。`create_ticket` 只给按钮接口，`query_faq` 由 `retrieve` 节点取代 |
  | 证据注入 | 渲染进 System Prompt 证据段。原因：DeepSeek 思考模式下，当前轮出现自造 tool_call id 会返回 400 |
  | 历史 | State `messages` 只由 `finalize` 追加，一轮失败历史不变；`messages` 表照写（挖掘任务读这张表） |
  | 兜底按钮 | 闸门兜底不带按钮（用户第 8 点只在投诉和 Agent 判断时给选项），用户未反对 |

- 设计阶段实测（一次性探测，不进仓库）：DeepSeek 思考模式下连续 3 次带工具调用（`query_order` → 并行 `query_product` + `query_logistics` → 收尾）没有返回 400；流式合并结果带 `usage_metadata`（含思考 token）；不绑定工具 + `TOOL_ROUND_CLOSING` 的强制收尾正常。
