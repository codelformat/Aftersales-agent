# ch01 纯对话 Implementation Plan

> **For agentic workers:** 本项目的执行方式由 `CLAUDE.md` 规定：Claude 把每个任务交给 Codex 实现，Codex 完成后由 Claude 审查 diff、运行测试、补记 dev-notes、提交并推送。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现一个售后客服对话服务：SSE 流式多轮对话，加售后描述的结构化提取。

**Architecture:** FastAPI 提供 3 个接口。对话用 LCEL 链 `ChatPromptTemplate | ChatOpenAI`，历史存储在进程内存，每次调用前用 `trim_messages` 按 2000 token 预算裁剪。提取用 `with_structured_output(method="function_calling")`，提取模型关闭思考。

**Tech Stack:** Python 3.12、uv、FastAPI ≥ 0.142（`fastapi.sse`）、langchain-core ≥ 1.6、langchain-openai ≥ 1.6、pydantic-settings ≥ 2.15、pytest ≥ 9、httpx（测试）、anyio pytest 插件（随 anyio 安装）。

**Spec:** `docs/superpowers/specs/2026-10-06-ch01-pure-chat-design.md`

## Global Constraints

- Python 版本：`requires-python = ">=3.12"`，用 `uv python pin 3.12` 固定。
- 依赖只通过 `uv add` / `uv add --dev` 添加。不添加本计划未列出的运行时依赖。
- 配置只读取 4 个环境变量：`CHAT_BASE_URL`、`CHAT_MODEL`、`CHAT_API_KEY`、`CHAT_THINKING`（可选）。
- 代码常量（`app/config.py`）：`TOKEN_BUDGET = 2000`、`CHARS_PER_TOKEN = 2.0`、`SHOP_NAME = "示例商城"`、`UPSTREAM_TIMEOUT_SECONDS = 60`、`UPSTREAM_MAX_RETRIES = 1`、`MAX_INPUT_CHARS = 2000`。
- token 计数一律用 `app.context.count_tokens()`，不直接调用 `count_tokens_approximately`。
- SSE 事件一律用 `ServerSentEvent(raw_data=json.dumps(payload, ensure_ascii=False), event=<name>)`。不用 `data=`，因为它把中文转义为 `\uXXXX`。
- 对外错误信息只用固定文案，不包含异常内容。完整异常用 `logger.exception` 写日志。
- 单元测试不访问网络。测试中的模型一律用 FastAPI `dependency_overrides` 替换。
- 异步测试用 `@pytest.mark.anyio`，客户端用 `httpx.AsyncClient(transport=ASGITransport(app=app), base_url="http://test")`。
- 代码注释和文档用中文，按 ASD-STE100 原则：短句、主动语态、一词一义。
- Codex 不执行 `git commit`、`git push`，不修改 `.env`、`CLAUDE.md`、`docs/`、`dev-notes/`。

## Review Focus

1. **客户端在流中断开**：期望不写入历史，且会话锁被释放，下一次请求不返回 409。→ Task 5 的 `test_stream_closed_early_writes_nothing_and_releases_lock`。
2. **用户消息含花括号**（例如 `订单{A1}`）：期望正常回复，不触发模板变量错误。→ Task 5 的 `test_message_with_braces`。
3. **只含空白的消息或空字符串 `session_id`**：期望返回 422，不调用模型。→ Task 5 的 `test_blank_message_rejected` 和 `test_empty_session_id_rejected`。
4. **`/extract` 响应中的中文**：期望 curl 直接显示"换货"，不显示 `换`。→ Task 6 的 `test_extract_response_is_utf8_not_escaped`。
5. **思考模式下上游返回 content 为空的 chunk**：期望不发送空的 `token` 事件。→ Task 5 的 `test_empty_chunks_are_skipped`。

接口与要点（已用 Context7 核对 langchain-openai 1.6：`extra_body` 会嵌入请求体，用于 OpenAI 兼容上游的非标准参数）：

```python
from functools import lru_cache

from langchain_core.language_models import BaseChatModel
from langchain_openai import ChatOpenAI

from app.config import UPSTREAM_MAX_RETRIES, UPSTREAM_TIMEOUT_SECONDS, Settings, get_settings


def _build(settings: Settings, thinking: str | None) -> ChatOpenAI:
    kwargs = {}
    # 只在配置了 CHAT_THINKING 时发送 thinking 字段。GPT、Ollama 不认识它。
    if settings.chat_thinking is not None and thinking is not None:
        kwargs["extra_body"] = {"thinking": {"type": thinking}}
    return ChatOpenAI(
        model=settings.chat_model,
        base_url=settings.chat_base_url,
        api_key=settings.chat_api_key,
        timeout=UPSTREAM_TIMEOUT_SECONDS,
        max_retries=UPSTREAM_MAX_RETRIES,
        **kwargs,
    )


def build_chat_model(settings: Settings) -> ChatOpenAI:
    return _build(settings, settings.chat_thinking)


def build_extract_model(settings: Settings) -> ChatOpenAI:
    # 强制 tool_choice 与 DeepSeek 思考模式冲突（400），所以提取时关闭思考。
    return _build(settings, "disabled")


@lru_cache
def get_chat_model() -> BaseChatModel:
    return build_chat_model(get_settings())
```

- [ ] **Step 3: 实现 `app/schemas.py`**

```python
from enum import Enum
from typing import Annotated

from pydantic import BaseModel, Field, StringConstraints

from app.config import MAX_INPUT_CHARS

UserText = Annotated[str, StringConstraints(strip_whitespace=True, min_length=1, max_length=MAX_INPUT_CHARS)]
SessionId = Annotated[str, StringConstraints(strip_whitespace=True, min_length=1, max_length=64)]


class RequestType(str, Enum):
    RETURN = "退货"
    EXCHANGE = "换货"
    REFUND = "退款"
    REPAIR = "维修"
    COMPLAINT = "投诉"
    INQUIRY = "咨询"


class AfterSalesRequest(BaseModel):
    """从用户的售后描述中提取的结构化信息。"""

    order_id: str | None = Field(None, description="原文中出现的订单号，保持原样；原文没有则为 null，不许编造")
    request_type: RequestType = Field(description="诉求类型，按系统提示中的判定规则选择")
    expected_solution: str = Field(description="用户想要的结果，不复述问题；用户没说明时写“未说明”")


class ChatRequest(BaseModel):
    session_id: SessionId | None = None
    message: UserText


class ExtractRequest(BaseModel):
    text: UserText
```

模板用 `ChatPromptTemplate.from_messages` 和 `MessagesPlaceholder`（已用 Context7 核对 langchain-core 1.6）。**注意：** 模板文本中不许出现字面花括号，因为花括号会被解析为模板变量。

```python
from datetime import date

from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

from app.config import SHOP_NAME

CHAT_SYSTEM_TEMPLATE = """你是{shop_name}的售后客服助手。今天是{today}。

## 职责
帮助用户处理退货、换货、退款、维修、投诉和售后咨询。

## 行为约束
1. 不编造订单状态、物流信息和店铺政策。你无法查询订单和物流。用户问到时，说明你无法查询，并建议用户联系人工客服核实。
2. 不承诺具体的退款金额或到账时间。
3. 超出你能处理的范围时，建议用户联系人工客服。
4. 只回答售后相关的问题。用户问无关问题时，礼貌拒绝，并引导回售后话题。
5. 用户要求转人工时，表示理解，并告诉用户可以联系人工客服。不要声称已经完成转接。

## 回复风格
使用中文。语气礼貌、简洁。每次回复不超过 200 字。"""

chat_prompt = ChatPromptTemplate.from_messages([
    ("system", CHAT_SYSTEM_TEMPLATE),
    MessagesPlaceholder("history"),
    ("human", "{input}"),
])


def render_chat_system(today: date) -> str:
    return CHAT_SYSTEM_TEMPLATE.format(shop_name=SHOP_NAME, today=today.isoformat())


EXTRACT_SYSTEM_PROMPT = """你是售后信息提取器。从用户的售后描述中提取订单号、诉求类型和期望方案。

## 诉求类型判定规则
- 退货：用户要把商品退回，并拿回货款。用户说“不想要了”“退了吧”且商品已在手上，判为退货。
- 换货：用户要把商品退回，换一件同款或其他款。
- 退款：用户只要钱，不涉及退回商品。例如：未发货就取消、少发、价保退差价、多扣款。
- 维修：用户要把商品修好，不要求换新。
- 投诉：用户对服务、物流或商家表达不满，主要诉求是追责、要说法或要求改进。
- 咨询：用户询问政策、流程或进度，没有提出具体的售后要求。

## 订单号规则
只提取原文中出现的订单号，保持原样，包括字母和横线。原文没有订单号时为 null。不许编造订单号。

## 期望方案规则
写用户想要的结果，例如“更换新耳机”“退回差价”。不复述问题本身。用户没有说明期望时，写“未说明”。"""

extract_prompt = ChatPromptTemplate.from_messages([
    ("system", EXTRACT_SYSTEM_PROMPT),
    ("human", "{text}"),
])
```

```python
from collections.abc import Sequence

from langchain_core.messages import BaseMessage, HumanMessage, SystemMessage
from langchain_core.messages.utils import count_tokens_approximately, trim_messages

from app.config import CHARS_PER_TOKEN


class BudgetExceeded(Exception):
    """系统提示加当前消息已超出预算。"""


def count_tokens(messages: Sequence[BaseMessage]) -> int:
    return count_tokens_approximately(messages, chars_per_token=CHARS_PER_TOKEN)


def build_history(
    history: Sequence[BaseMessage], system_text: str, user_input: str, budget: int
) -> list[BaseMessage]:
    fixed = count_tokens([SystemMessage(system_text), HumanMessage(user_input)])
    if fixed > budget:
        raise BudgetExceeded
    return trim_messages(
        list(history),
        max_tokens=budget - fixed,
        strategy="last",
        token_counter=count_tokens,
        start_on="human",
    )
```

- Produces:
  - `app.services.chat.ChatTurn`（dataclass：`session: Session`、`history: list[BaseMessage]`、`user_input: str`、`today: date`）
  - `app.services.chat.stream_reply(turn: ChatTurn, model: Runnable) -> AsyncIterator[tuple[str, dict]]`：产出 `(事件名, 数据)`
  - `app.api.chat.get_token_budget() -> int`：FastAPI 依赖，返回 `TOKEN_BUDGET`
  - `app.api.chat.get_today() -> date`：FastAPI 依赖，返回 `date.today()`
  - `app.api.chat.prepare_chat_turn(...) -> ChatTurn`：FastAPI 依赖
  - `app.main.app: FastAPI`

**流程要求（来自 spec 9.2）：**

- `prepare_chat_turn` 按顺序执行：
  1. `store.get_or_create(req.session_id)`。
  2. 如果 `session.lock.locked()`，抛出 `HTTPException(409, detail={"code": "session_busy", "message": "该会话正在处理上一条消息，请稍后重试"})`。
  3. 调用 `build_history(session.messages, render_chat_system(today), req.message, budget)`。如果抛出 `BudgetExceeded`，抛出 `HTTPException(422, detail={"code": "budget_exceeded", "message": "消息过长，请缩短后重试"})`。
  4. `await session.lock.acquire()`。第 2 步到第 4 步之间没有 `await`，所以检查和获取之间不会切换协程。
  5. 返回 `ChatTurn`。
- `stream_reply` 按顺序产出：
  1. `("session", {"session_id": ...})`。
  2. 对 `(chat_prompt | model).astream({"shop_name": SHOP_NAME, "today": turn.today.isoformat(), "history": turn.history, "input": turn.user_input})` 的每个 chunk：如果 `chunk.content` 是非空字符串，产出 `("token", {"text": chunk.content})`，并累加到缓冲区。
  3. 正常结束后：向 `turn.session.messages` 追加 `HumanMessage(turn.user_input)` 和 `AIMessage(缓冲区)`，然后产出 `("done", {"finish_reason": "stop"})`。
  4. 如果第 2 步抛出 `Exception`：`logger.exception(...)`，产出 `("error", {"code": "upstream_error", "message": "服务暂时不可用，请稍后重试"})`，不写历史。不要捕获 `BaseException`。原因：客户端断开时生成器收到 `GeneratorExit` 或 `CancelledError`，此时不能写历史，也不能再产出事件。
- 端点是 yield 型异步生成器，`response_class=EventSourceResponse`（已用 Context7 核对 FastAPI 0.142 `fastapi.sse`）。它把 `stream_reply` 的每个元组转换为 `ServerSentEvent(raw_data=json.dumps(data, ensure_ascii=False), event=name)`，并在 `finally` 中执行 `turn.session.lock.release()`。
- **为什么预检放在依赖中：** FastAPI 0.142.2 实测，在 yield 型 SSE 端点的函数体内抛出 `HTTPException`，客户端收到 200 和空流。在依赖中抛出时，客户端收到正常的 422 或 409。
