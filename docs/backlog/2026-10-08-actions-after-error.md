# 本轮出错后，人工选项按钮仍可点击

- 状态：搁置
- 发现：ch05 全分支代码审查，2026-10-08

## 1. 现象

Agent 调用 `offer_human_options` 后发出 `actions`，随后强制收尾调用失败，前端收到 `error`。这一轮不写库、不进 State，但「建工单」按钮仍可点。点击后工单提示进入 State，前面没有用户消息；`build_history`（`start_on="human"`）会把它裁掉，Agent 下一轮看不到工单号。

## 2. 根因

`app/web/index.html` 的 `showError` 没有处理已渲染的按钮。

## 3. 当时的决定和理由

搁置。用户出错后仍想建单是合理诉求，工单本身会正常写入；影响只是下一轮 Agent 看不到提示。

## 4. 建议方案和改动范围

前端：`showError` 时禁用本轮的按钮，或保留按钮但在建单成功后提示"请重新描述问题"。后端可选：`POST /tickets` 在 State 没有用户消息时，把提示写成"用户消息 + 助手消息"一对。

## 5. 验收方法

浏览器中模拟一轮在 `actions` 之后出错，检查按钮状态；或点击后下一轮问"工单号多少"，Agent 能答出。
